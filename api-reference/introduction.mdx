## Base URL

```text
https://api.solmarket.app/api/v1
```

<Note>
  The API stores metadata and verifies confirmed Solana transactions. It does not custody funds, sign user transactions, or accept client-provided financial amounts as truth.
</Note>

---

## Authentication

SolMarket uses two wallet authentication modes.

| Mode | Headers | Used by |
|------|---------|---------|
| Wallet header | `x-wallet-address` | Legacy user reads and financial transaction recording after the user has already signed on-chain |
| Signed wallet request | `x-wallet-address`, `x-wallet-message`, `x-wallet-signature` | Admin actions and holder-gated proposal flows |

Signed requests use a base64-encoded JSON message with this shape:

```json
{
  "wallet": "<wallet public key>",
  "method": "POST",
  "path": "/api/v1/markets/proposals",
  "ts": 1710000000000,
  "nonce": "random-unique-nonce"
}
```

The signature must be an Ed25519 wallet signature over the raw message bytes. The backend checks method, path, timestamp, nonce, wallet, and signature validity.

<Warning>
  Admin endpoints require signed wallet headers. The wallet must be the oracle authority or appear in `ADMIN_WALLETS`.
</Warning>

## Markets

| Method | Endpoint | Auth | Description |
|--------|----------|------|-------------|
| `GET` | `/markets` | Public | List markets. Supports `status`, `q`, `limit`, and `verify=false`. |
| `GET` | `/markets/protocol/stats` | Public | Protocol volume, fees, buyback, burn, and holder-gate stats. |
| `GET` | `/markets/:id` | Public | Fetch one market and verify active market PDA state. |
| `GET` | `/markets/:id/bets` | Public | Paginated bet history for one market. |
| `GET` | `/markets/:id/price-history` | Public | Stored market price history. |
| `GET` | `/markets/:id/token-price-history` | Public | Stored token price history. |
| `POST` | `/markets` | Signed admin | Create a market directly and seed initial liquidity. |

Query examples:

```bash
curl "https://api.solmarket.app/api/v1/markets?status=active&q=BONK&limit=50&verify=false"
curl "https://api.solmarket.app/api/v1/markets?q=CA:So11111111111111111111111111111111111111112"
```

## Financial recording

The frontend submits the on-chain transaction first. The API records it only after verifying the confirmed transaction on Solana.

| Method | Endpoint | Auth | Verification |
|--------|----------|------|--------------|
| `POST` | `/markets/:id/bet` | `x-wallet-address` | Parses `buy_tickets`, validates wallet/market/vault/user ATA, and derives side, tickets, paid amount, price, and `max_cost` from chain data. |
| `POST` | `/markets/:id/claim` | `x-wallet-address` | Parses claim/refund transaction and derives the realized USDC delta from chain data. |

Client-supplied `tickets`, `totalPaid`, and `amount` are treated as hints only. The backend records the values verified from the transaction.

## Holder proposals

| Method | Endpoint | Auth | Description |
|--------|----------|------|-------------|
| `POST` | `/markets/proposals` | Signed wallet | Submit a holder-gated market proposal. |
| `GET` | `/markets/proposals` | Signed admin | List pending proposals. |
| `POST` | `/markets/proposals/:id/approve` | Signed admin | Re-check holder eligibility and approve or attach a market ID. |
| `POST` | `/markets/proposals/:id/reject` | Signed admin | Reject a proposal. |

Current implementation checks an absolute project-token balance. The production target is a supply-share gate: `1%` in bootstrap phase and `0.5%` in expansion phase.

## Error shape

Errors return JSON with an `error` string:

```json
{
  "error": "Transaction verification failed"
}
```

Common status codes are `400` for invalid input, `401` for missing or invalid wallet authentication, `403` for unauthorized admin or holder actions, `404` for missing records, and `409` for duplicate financial transactions.
